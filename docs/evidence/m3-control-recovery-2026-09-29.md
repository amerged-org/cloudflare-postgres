# Control-state capture and quarantined recovery qualification

The generic `recover-control` operator command captures authoritative Cloudflare
D1 state, seals it with explicitly supplied credential keyrings and verifies exact
reconstruction in a private offline SQLite artifact. Cloudflare remains the live
control authority. This qualification does not activate recovered state or
complete production disaster recovery.

## Bounded resumption and tests

The [original held checkpoint](m3-control-recovery-held-2026-09-29.md) retains the
initial two-attempt D1 stop and all earlier local corrections. The user explicitly
requested continuation. The resumed work preserves the same two Node cases and
one native qualification case; no matrix, new case or gate repetition is added.
Integration onto current main retains Fleet inspection and its dependencies.

The first resumed renderer avoids D1's compound-SELECT limit but the actual
capture fails in 1.694 seconds. A private read-only diagnostic identifies
`Expression tree is too large (maximum depth 100)`. Balanced concatenation of the
same scalar table subqueries is the second narrow correction. The unchanged
named local cases pass in 1.725 seconds, and actual capture passes in 1.744 seconds.
No further renderer correction is made. The query preserves one read, deterministic
ordering, tagged cell types and exact integers, with a 95,000-byte SQL bound,
32-column encoder bound and a 2,000,000-byte returned-string bound. These respect
[Cloudflare's documented D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

The original two local cases fail meaningfully first and cover all current
migrations, an AUTOINCREMENT high-water mark above JavaScript's exact integer
range, current/historical credential and fence ciphertext generated by the actual
Worker implementation, exact reconstruction, tamper/wrong keys/missing historical
custody, private output, no overwrite and redacted CLI errors. Existing assertions
are preserved. After freezing, one canonical format/lint/typecheck/Vitest/Node
gate passes; 27 Worker and 36 Node cases pass, with six unchanged Go cases retained
as prior source-valid evidence: 69 automated cases. Go checks are not rerun.

## Actual Dev evidence

The selected amerged Dev D1 database is captured through authenticated Wrangler
with explicit account/binding identity, private strict JSON configuration and an
empty environment file. The command has fixed read-only SQL and bounded execution,
output and cancellation; raw provider output is private. It issues no D1 write,
Worker-secret write, infrastructure order or customer PostgreSQL request.

Actual results:

- One snapshot contains 40 tables, 47 rows, 121 schema objects and 14 migrations.
- The snapshot is 64,736 bytes; the encrypted bundle is 87,049 bytes.
- Sealing passes in 0.711 seconds; independent offline restoration passes in
  0.532 seconds, using a separately generated 32-byte recovery key.
- Exact reconstruction, integrity, foreign keys and both existing operator-held
  credential keyrings are verified. All output files are mode 0600 in a mode-0700
  directory. Existing output paths are never replaced.
- Dev has zero role credentials and allowance reservations. This live sample
  supplies no positive ciphertext-row proof; the unchanged local cases provide
  that proof using actual Worker-generated ciphertext.

An additional read-only report initially selected a nonexistent `allowance_fences`
table; a wrong working directory then prevented its next file read. Neither
changes the source or repeats capture. The final report uses the committed
`allowance_reservations` table and verifies the same restored artifact. Both
report errors remain in private evidence.

The frozen source receives independent bounded review with no material defect.
Actual local secret values and encodings match none of the changed public files.
The ignored `.env.local` and `.dev.vars` remain byte-identical and untracked.
The live Worker version, D1 migrations/Secrets and server workloads are unchanged
by this operator-only delivery.

## Recovery boundaries

Restoration executes only independently loaded trusted migration SQL; captured
SQL never grants execution authority. AEAD binds bundle domain, version and source.
Every retained encrypted credential must authenticate against the supplied
historical key custody. Publication is exclusive, with the manifest last; an
incomplete directory after a crash is unverified and cannot be overwritten.

The result states `activationSupported: false`; the manifest additionally states
`recoveryFencesImplemented: false`. Historical tokens, leases, allowances and
operations are neither renewed nor replayed. Do not connect this SQLite artifact
to regional controllers.

The local qualification archive and recovery key share the operator workstation;
independent off-node archive/key custody is not qualified. Complete recovery still
requires global fencing, external-resource reconciliation, provider/Worker/Talos
credential custody, fresh Cloudflare bootstrap and a rehearsed safe activation
procedure. PostgreSQL physical backups, WAL, PITR and safe retention remain
separate required work. See the [contract](../contracts/control-recovery-v1.md)
and [operator workflow](../../apps/regional-controller/README.md#control-recovery-artifacts).
