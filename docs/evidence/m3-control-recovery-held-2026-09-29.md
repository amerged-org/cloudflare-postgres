# Control recovery candidate held at D1 qualification

The isolated `codex/control-recovery` candidate implements a generic operator
chain: one canonical-state read, encrypted recovery bundle and verified offline
database/key reconstruction. Cloudflare remains authoritative; reconstructed
state is quarantined with activation unsupported. The candidate is not merged or
deployed and does not complete production control-service recovery.

## Actual local evidence

The baseline is 65 automated cases. Exactly two new Node cases use all 14 current
committed migrations, known D1 migration metadata, an integer high-water mark
above JavaScript's exact range, and historical/current role plus allowance
ciphertexts generated by the existing Worker code. They cover exact reconstruction,
every retained credential's decryptability, wrong-key/tamper/missing historical
custody, private files, no-overwrite behavior and redacted CLI output. A third
independently reported case is the actual read-only Dev capture; no matrix or
additional suite is added.

Both local cases fail meaningfully first in 0.757 seconds. The initial core
attempt exceeds the unchanged 95,000-byte SQL bound and fails in 0.329 seconds.
One compact cell-conversion correction reduces the single statement to 86,208
bytes; both cases pass in 1.519 seconds. A review then exposes a wrong snapshot
digest being accepted for sealing. That defect fails inside the same existing
case in 0.288 seconds; one narrow correction reuses trusted offline validation
before sealing. Exclusive directory creation and a last-published manifest replace
the directory-rename overwrite race. Both named cases pass in 1.910 seconds.

The trusted local migration set supplies restoration SQL; captured SQL is never
execution authority. The encrypted bundle covers snapshot and both keyrings,
with source/domain/version binding and an independently supplied recovery key.
Its restore result reports `activationSupported: false`; its manifest also reports
`recoveryFencesImplemented: false`. No historical token, lease, allowance or
operation is renewed or replayed.

## Actual D1 stop and diagnosis

The live case first demonstrates the missing capture mode. Candidate one fails in
2.057 seconds before producing a snapshot: Wrangler's array-valued `--env-file`
option consumes command words when placed before the subcommand. One argument-order
correction fixes that invocation. Candidate two still fails in 2.419 seconds and
produces no snapshot. The two-attempt stop is reached: no third capture, full gate,
source publication or runtime deployment occurs.

Bounded post-stop metadata reads establish valid authentication, 14 applied
migrations and exact agreement between all 121 actual and expected schema objects.
They do not capture application data. `EXPLAIN QUERY PLAN` then gives the precise
provider failure: `too many terms in compound SELECT`. The local SQLite engine
accepts the candidate's 40-table UNION construction; D1 does not. Passing the
local cases therefore does not qualify remote capture. [D1 limits](https://developers.cloudflare.com/d1/platform/limits/).

The smallest proposed next correction replaces that UNION construction with a
bounded JSON array of the same table subqueries, preserving one consistent read,
exact types, schema checks and all output limits. It remains unapplied. A narrowly
scoped exception was requested for this correction and the separately identified
budget-history/type and PostgreSQL-portability/fixture corrections; a submitted
question is not approval.

Nine draft files remain hash-sealed in the ignored worktree. The canonical full
gate has not run. The Dev Worker, schema and servers are untouched. The private
environment and all prior held candidates remain protected.
