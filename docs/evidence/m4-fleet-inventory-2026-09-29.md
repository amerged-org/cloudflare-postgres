# Provider inventory and enrolled fleet inspection

The candidate adds an installation-only Contabo read API and a generic operator
inspector that compares explicit provider/Node enrollment. The optional
maintenance guard can invalidate stale identity evidence; it grants no machine,
capacity or execution authority. Full M4 maintenance/recovery remains open.

## Bounded source evidence

The baseline is 65 automated cases. Exactly three independently reported cases
cover this delivery: one Worker authority/provider-protocol case, one Node
association/maintenance-boundary case and one actual Dev read-only qualification.
The Worker case first fails on missing authorization behavior (404 instead of
401), then passes in 1.40 seconds. The Node case first fails on missing inspection,
then passes. A concrete global-TLS bypass defect fails inside that same case;
the narrow static-auth boundary correction passes the final named file in
0.647 seconds. No matrix or speculative suite is added.

The local checks establish installer-only dispatch, fixed OAuth/list hosts,
bounded observed pagination, duplicate rejection, selected metadata and private
credential handling. Node checks establish explicit association, missing/replaced
host exclusion, an unmanaged builder and no maintenance Job effects. Static
credentials and verified TLS keep credential resolution inside the intended
network observation boundary; local file loading precedes that timer.

The exact existing Kubernetes-client dependency versions of `js-yaml`/its types
are pinned directly for pre-SDK validation; no new distribution versions or source
fork is introduced. The [contract](../contracts/fleet-inventory-v1.md) and OpenAPI
describe the current read shape. The default controller, D1 schema and customer
admission are unchanged by this slice.
